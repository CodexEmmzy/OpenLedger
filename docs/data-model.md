# Ledger Data Model

The journal is authoritative. `account_balances` is a transactionally maintained projection used for fast reads; it can be recomputed from posted entries and checked by the repository invariant checker.

```mermaid

    ACCOUNTS ||--|| ACCOUNT_BALANCES : projects
    ACCOUNTS ||--o{ ENTRIES : receives
    TRANSACTIONS ||--|{ ENTRIES : contains
    TRANSACTIONS ||--o{ TRANSACTION_STATUS_HISTORY : records
    TRANSACTIONS o|--o| TRANSACTIONS : reverses

    ACCOUNTS {
        uuid id PK
        text account_code UK
        text external_ref UK
        char currency
        enum kind
        enum type
        enum status
        boolean allow_negative
    }
    ACCOUNT_BALANCES {
        uuid account_id PK_FK
        bigint balance_minor
        bigint version
        timestamptz updated_at
    }
    TRANSACTIONS {
        uuid id PK
        varchar idempotency_key UK
        char request_hash
        enum type
        enum status
        char currency
        uuid reversal_of UK_FK
        timestamptz created_at
    }
    ENTRIES {
        bigint id PK
        uuid transaction_id FK
        uuid account_id FK
        enum direction
        bigint amount_minor
        timestamptz created_at
    }
    TRANSACTION_STATUS_HISTORY {
        bigint id PK
        uuid transaction_id FK
        enum previous_status
        enum status
        text reason
        timestamptz changed_at
    }
```

## Invariants

- Each account has exactly one balance projection. Account creation inserts the zero-valued projection in the same database transaction.
- An account's currency and accounting classification cannot change after creation.
- Customer wallet accounts are credit-normal liabilities. Debit entries reduce their spendable balance; the database rejects a result below zero.
- System account negative-balance permission is explicit and stored on the account.
- Each entry amount is a positive `BIGINT` integer minor-unit quantity. Entries cannot be updated, deleted, or truncated.
- Each transaction has a globally unique idempotency key and one currency. Entry accounts must use that currency.
- A posted transaction has at least two distinct accounts, at least one debit and credit, and equal debit and credit totals. A deferred constraint trigger checks this at commit.
- Entry insertion adjusts the balance projection in the same database transaction. An overdraft or failed deferred check rolls back both entries and projection changes.
- A reversal is a new transaction whose entries exactly negate the referenced posted transaction. The original journal rows remain unchanged.
- Status history is generated by database triggers and is append-only.

## Normal-Side Projection

Balances are stored as positive on the account's normal side. For asset and expense accounts, debits increase and credits decrease the projection. For liability, equity, and income accounts, credits increase and debits decrease it. This allows customer wallet liability balances to be represented as positive spendable balances while preserving standard debit/credit journal semantics.
